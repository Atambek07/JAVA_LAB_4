# Гайд: куда и как писать код (не меняя существующий)

Этот файл — только справочник. Он объясняет:

1. **Куда писать код** (в какую папку и пакет класть новый файл).
2. **Как писать код** (какие аннотации, соглашения, слои использовать).
3. **Какие задания может дать преподаватель** (несколько вариантов), и куда в каждом случае дописать код.

**Важно:** существующий код изменять не нужно — только добавлять новые файлы и (при необходимости) новые методы в существующие сервисы/контроллеры.

## 1. Структура проекта (две части)

В корне репозитория два независимых Java-проекта:

| Папка | Что это | Сборка |
|-------|---------|--------|
| `..` | Полноценный Spring Boot REST API «Библиотека» (лаба № 5: пагинация, спецификации, оптимистическая блокировка, тесты, Docker/PostgreSQL) | Maven (`mvn`) |
| `../../LibraryProject` | Простая консольная ООП-лаба (книги, читатели, отчёты, тесты) | Maven (`mvn`) |

Оба используют один пакет: `kg.course.library`.

| Тест на новую функцию | `../src/test/java/kg/course/library` или `LibraryProject/src/test/...` | `GenreServiceTest.java` | `@WebMvcTest`, `@DataJpaTest`, `@SpringBootTest` или обычный JUnit 5 |

## 3. Как писать код — соглашения проекта

- **Пакет:** `kg.course.library` и подпакеты (`entity`, `repository`, `web`, `config`).
- **Имена классов:** `PascalCase` (`BookRepository`, `CreateBookRequest`).
- **Имена методов/полей:** `camelCase` (`findByTitle`, `pageSize`).
- **Сущность БД:** `@Entity` + `@Table` + `@Id` (+ `@Version` для оптимистической блокировки).
- **Репозиторий:** интерфейс, `extends JpaRepository<Сущность, ТипId>`. Дополнительные поисковые методы — по名前ним правилу Spring Data (`findBy...`) или через `@Query`.
- **Сервис:** `@Service`. Вся бизнес-логика живет здесь. Контроллер только вызывает сервис.
- **Контроллер:** `@RestController` + `@RequestMapping("/api/...")`. Только HTTP-запросы/ответы. Не содержать бизнес-логику.
- **DTO:** отдельные классы/records в `web/` (`*Request`, `*Response`). Не возвращайте клиенту JPA-сущности напрямую.
- **Валидация:** `@Valid` на теле запроса, `@NotBlank`, `@NotNull`, `@Positive` и т.д.
- **Ошибки:** выбрасывайте исключения в сервере, а `ApiExceptionHandler` (`@ControllerAdvice`) превращает их в ответ `application/problem+json` (RFC 9457).
- **Тесты:** пишите в `src/test`, не смешивайте с основным кодом. Для лабы №5 используются `@WebMvcTest` (контроллеры), `@DataJpaTest` (репозитории + Testcontainers), `@SpringBootTest` (интеграция).
- **Правило для этого задания:** существующий код не меняем — добавляем только новые файлы или новые методы в уже существующие сервисы/контроллеры.

## 4. Варианты заданий, которые может дать преподаватель

Ниже несколько типичных вариантов. Для каждого указано, **что и куда писать**. Существующий код не трогаем.

### Вариант 1. Новая сущность + полный CRUD
*Пример:* добавить сущность **Жанр (Genre)** книги и возможность управлять жанрами через API.

- `entity/Genre.java` — новая JPA-сущность.
- `db/migration/V5__add_genre.sql` — таблица `genres`.
- `repository/GenreRepository.java` — `JpaRepository<Genre, Long>`.
- `web/GenreController.java` — `GET /api/genres`, `POST /api/genres`, `PUT /api/genres/{id}`, `DELETE /api/genres/{id}`.
- `web/CreateGenreRequest.java`, `web/GenreResponse.java` — DTO.
- опционально: метод в `LibraryService.java`, если нужна дополнительная логика.

### Вариант 2. Дополнительная фильтрация / поиск
*Пример:* поиск книг не только по названию/автору, но и по **издателю** или **категории**.

- добавить поле в `entity/Book.java` + миграция (`V6__...sql`).
- `repository/BookSpecifications.java` — новый метод спецификации (в стиле существующих).
- в `web/BookController.java` — новый параметр запроса в `/api/books/search` (не удалять старые).

### Вариант 3. Новый отчёт
*Пример:* эндпоинт `GET /api/reports/overdue` — список просроченных выдач.

- `library/LibraryReports.java` — метод формирования отчёта (или новый сервис).
- `web/ReportController.java` — новый метод с `@GetMapping("/api/reports/overdue")`.
- `web/OverdueReportResponse.java` — DTO ответа.

### Вариант 4. Валидация и кастомное исключение
*Пример:* при выдаче книги проверять, что у читателя нет более 3 активных книг, иначе ошибка.

- `library/LibraryService.java` — добавить проверку в метод выдачи (`loanBook`).
- `library/LimitExceededException.java` (или существующее) — исключение, которое бросает сервис.
- `web/ApiExceptionHandler.java` — уже есть, он обработает исключение и вернёт `application/problem+json`.

### Вариант 5. Написать тесты для нового функционала
*Пример:* после добавления нового эндпоинта покрыть его тестами.

- `src/test/java/kg/course/library/GenreControllerTest.java` — `@WebMvcTest`.
- `src/test/java/kg/course/library/GenreRepositoryTest.java` — `@DataJpaTest` + Testcontainers.
- или в `../../LibraryProject/src/test` — обычные JUnit 5 тесты (`LibraryTest.java`, `LibraryLab2Test.java` как пример).

### Вариант 6. Добавить пагинацию в список
*Пример:* список читателей или книг должен возвращать `PageResponse<T>` с параметрами `page`, `size`, `sort`.

- `web/*Controller.java` — изменить сигнатуру метода списка на `Pageable pageable`, вернуть `PageResponse<...>`.
- `web/PageResponse.java` — уже есть, использовать как обёртку.

### Вариант 7. Миграция БД + новая функция
*Пример:* добавить таблицу `book_reservations` (бронирование книг).

- `db/migration/V7__add_reservations.sql`.
- `entity/BookReservation.java`.
- `repository/BookReservationRepository.java`.
- `web/BookReservationController.java` + DTO.
- сервисный метод в `LibraryService.java` или новом сервисе.

## 5. Как проверить, что написано

В папке `..`:

```bash
cd library

# запустить только тесты
mvn clean test

# тесты + отчёт покрытия JaCoCo (порог 60%)
mvn clean verify

# собрать без тестов
mvn package -DskipTests

# запустить приложение на http://localhost:8080
mvn spring-boot:run
```

После запуска:
- Swagger UI: `http://localhost:8080/swagger-ui.html`
- OpenAPI: `http://localhost:8080/v3/api-docs`
- Отчёт покрытия: `target/site/jacoco/index.html`

В папке `../../LibraryProject` — аналогично `mvn clean test` / `mvn spring-boot:run` (зависит от наличия `main`-метода).

---

**Кратко:** кладите JPA-сущности в `entity/`, репозитории в `repository/`, бизнес-логику в сервисы, контроллеры и DTO в `web/`, настройки в `application.properties`, миграции в `db/migration/`, а тесты — в `src/test`. Существующий код не меняйте — только добавляйте новое.
